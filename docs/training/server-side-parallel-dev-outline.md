# 服务端多线并行开发（ClawBench 实操演示大纲）

面向团队内部工程师。每节标注现场要演示什么，细节由演示者自行展开。

---

## 第 1 章 为什么转向服务端

### 开发效率的瓶颈在 Check

- 开发的本质是 PDCA 循环（Plan Do Check Action）
- Check，即测试，是影响开发效率的瓶颈
  - 要对：就得有大量测试覆盖
  - 要快：就得提升硬件性能
  - 要久：做到全天候执行
- PC 端 Windows 环境难以满足高频海量的测试需求（单元测试，或探索性集成测试）
  - 性能：核心和内存都比较紧张
  - 环境友好性：脚本支持度、编码、换行符

### 使用服务端的优势

- 环境：搭建一次，全员共享；基于镜像源可无感安装自定义软件包
- 性能：数十核心和数百 G 内存，能够支撑大型项目的测试执行
- 不断电：能够利用夜晚的垃圾时间执行定时或长程任务

## 第 2 章 调整固有思维，适应 AI 原生开发

### 2.1 把工作全部纳入 AI 体系

- 不只代码——需求、调研、文档、排障、运维，都走同一个入口
- 会话即工作单元：每件事有对应的会话、上下文、可回溯的过程
- 收益：上下文不丢、经验可复用、切换成本极低
- ▸ 演示：一件非编码的事（如查日志 / 写文档）也用会话完成

### 2.2 用 AI 的眼睛看代码

- 停止逐行纠结实现细节，改为看**意图、边界、影响面**
- 人会读的代码量下降，判断量上升：这段改动会不会破坏别处、有没有漏改
- 判据从「写得对不对」变成「行为和约束对不对」
- ▸ 演示：让 AI 讲清一处改动的影响面，自己只做判断

### 2.3 把执行交给 AI，你审证明：学会有选择的懒

- **减少自己写和做**：AI 是手，你是方向——能量花在定目标、划边界、做取舍
- 「懒」是有选择的：能委派的委派，必须自己拍的板不省；反例是事事亲力亲为 = 把自己变成 AI 的瓶颈
- **但委派不等于放手**：面对「到底真解决了没」，第一反应不是自己去验，而是让 AI 想办法**向你证明**它解决了
- 要证据链而不是结论：跑了什么、看到什么、边界情况怎么处理、失败路径如何
- 你的工作从「验证结果」升级为「挑证明的漏洞」——举证不足、循环论证、只测 happy path、结论与证据不匹配
- 反例：AI 说「已修复」就信了；或者反过来自己埋头重跑一遍，既浪费你的时间，也放弃了审逻辑的价值
- 共享资源纪律：多只手在同一棵树上，须避让（跑测试前先看别人在不在跑）
- ▸ 演示一：同一任务，一次自己写、一次交给 AI，对比耗时
- ▸ 演示二：让 AI 自证一处修复，追问「你怎么知道修好了 / 反例是什么 / 如果这个前提不成立呢」，当场挑出证明里的漏洞

### 2.4 不懂就去学：AI 输出不是黑箱

- 把 AI 的产出当**学习材料**，不是当答案抄
- 遇到不认识的 API / 模式 / 报错，当场弄懂，而不是绕过去
- 这决定长期能力：能审出证明漏洞的前提是看得懂它在做什么
- 反例：一直不学 = 只会越来越依赖，判断力持续退化
- ▸ 演示：挑一处 AI 用的陌生写法，追问它「为什么这样写 / 有什么替代」

## 第 3 章 单人多线并行（四个机制）

### 3.1 多会话切换
- 多会话 / 会话标签 / 未读计数 / 归档
- **会话 Fork**：从任意消息分叉，原分支不受影响
- 项目热切换后输入草稿保留

### 3.2 多 Worktree
- Git 面板创建 / 切换 / 浏览 worktree（状态徽标）
- 一条线一个 worktree，主工作区不受污染
- 聊天里 worktree 路径标注 → 直接跳转
- 纪律：只 `git add` 明确路径，不用 `git add -A`

### 3.3 多项目切换
- 项目 = 上下文边界（cookie / 会话归属）
- 跨项目跳转：切项目 → 等会话就绪 → 进聊天

### 3.4 跨项目通知
- 「其他项目」tab 巡检：运行中 / 未读 / **待审批**
- 被动提醒：应用内完成卡片 / 悬浮窗 / 灵动岛 / 系统推送 / 钉钉飞书
- 重点演示：一条线卡在待审批，切走后靠 tab 与卡片捞回

### 3.5 资源避让
- 跑测试前 `ps` 查他人是否在跑
- 隔离测试优先于全量
- build 与全量 vitest 不同时跑

## 第 4 章 常见问题（症状 → 解法）

- 两会话改同一文件改乱 → worktree 隔离
- 切项目回来消息 / 输入没了 → 草稿恢复、消息以 DB 为准
- 提交卷走他人改动 → 逐文件看 diff 再 add
- 测试超时 / 成片失败 → 并发争抢，隔离单跑
- 会话卡着不动 → 待审批
- 代码与 diff 对不上 → 并发 Agent 改了同一文件，比 mtime
- 杀进程误伤主服务 → 只按端口 / 记录过的 PID
