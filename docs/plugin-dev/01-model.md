# 01 · 模型：常驻页签、可选插件、三种开关

## 1. 一个插件由什么组成

一个 Dock 插件在当前版本有四块：

| 块 | 现在在哪 | 说明 |
|---|---|---|
| 身份 | `DOCK_TABS`（`dockTabs.ts`） | id、标题、描述、分组、能否隐藏、功能/能力标记 |
| 图标 | `dockTabMeta.ts` 或功能 `dock.ts` 的 `icon` | 静态图标在 meta；随状态变的（Forge）在 `dock.ts` |
| 面板 | 功能 `dock.ts` 的 `panel.load` | 由 `DockPanelHost` 统一渲染；核心文件管理/文件浏览仍在 App.vue |
| 行为 | 功能 `dock.ts` | 角标、可用性、`onEnter`、后台资源 |

下一阶段会把“图标 + 面板 + 行为”收进每个功能自己的 `dock.ts`，见 [04-runtime.md](04-runtime.md)。当前先按现状写。

## 2. 常驻页签 vs 可选插件

`DOCK_TABS` 里的 `closable` 决定用户能不能在管理器里关掉它。

| 类型 | `closable` | 例子 | 规则 |
|---|---|---|---|
| 常驻 | `false` | 文件管理、文件浏览、设置 | 永远可见，管理器里开关灰显并写“常驻” |
| 可选 | `true` | 其余 11 个 | 可以隐藏、可以排序 |

`chat` 不在 `DOCK_TABS` 里：它是右栏常驻面板，窄屏时是底部 Dock 的第一个按钮，不参与左栏列表。

为什么这三项不能关：

- **文件管理**：很多跳转（任务打开文件、通知跳转、空状态按钮）默认落到 `browse`。它一关，这些路径就没有落点。
- **文件浏览**：打开文件的唯一去处。
- **设置**：功能编排在设置里；设置一关，用户就再也打不开被关的插件了。

**通知中心可以关**，因为它只是“读入口”：通知在产生时就已经推送出去了（系统通知、钉钉/飞书），日志本身也是只追加的。藏掉页签不影响任何机制，所以它是**没有 `feature` 的可选页签**——关它只写本机偏好，不碰服务端。

## 3. 左栏是一条有序列表，没有固定头部

旧模型把页签分成「固定头部（`primary`）+ 可排序尾部 + 固定尾部（`settings`）」。现在没有这三段了：

- `primary` 标记、固定头过滤函数、可排序集合与「可排序尾部」函数**全部删除**；
- 宽屏 Dock 是**一个** `v-for`，窄屏是同一个列表按可用宽度分成“内联 + 溢出菜单”；
- 14 个页签**全部可拖**，包括三个常驻页签和 `settings`；
- 常驻只表示“不能隐藏”，不表示“位置固定”。

渲染入口只有一个：

```ts
import { dockTabs } from '@/composables/dockTabs'

const visible = computed(() =>
  dockTabs({
    hidden: hiddenDockTabs.value,            // 用户隐藏
    unavailable: unavailableDockTabs.value,  // 能力/运行时
    featureDisabled: featureDisabledDockTabs.value, // 服务端功能关闭
    order: dockTabOrder.value,               // 用户顺序
  }),
)
```

不要在 App.vue 之外再写一套“先取头部再取尾部”的拼接——旧 bug（页签渲染了但点不动）就是渲染列表和切换白名单各维护一份造成的。

## 4. 三种开关

这是整个模型最重要的一刀。三种“关闭”不是一回事：

| 类型 | 谁决定 | 关掉后 | 现有例子 | 功能编排里的控件 |
|---|---|---|---|---|
| 能力 capability | 设备/宿主 | 不是关，是本来就没有 | 终端（PTY）、端口映射（没有可用传输） | 灰掉 + 行内原因 |
| 功能 feature | 服务端配置 | 服务端也停 | Forge（停轮询、清绑定）、邮件（停 IMAP 同步）、终端、知识库、任务、分享 | 真开关（写服务端） |
| 偏好 preference | 这个客户端 | 只是不在左栏显示 | 历史、统计、会议、端口映射 | 显示开关 |

### 4.1 组合规则

```
可见 = 能力可用 && 功能已开 && (常驻 || 用户没有隐藏)
```

- 常驻页签不受偏好影响。
- 能力不满足时，即使功能开着、用户没隐藏，也不可见。
- 功能关闭时，左栏不渲染；如果当前正打开它，宿主切到兜底页签。
- 偏好隐藏只影响入口，已经挂载的面板保持挂载，状态不丢；客户端角标轮询（邮件未读）会停。

原因优先级：能力 > 功能 > 偏好。管理器只显示最根本的一条。

### 4.2 当前代码怎么落

- **偏好**：`useDockPlugins` 的 `hidden` 集合，由管理器写入。
- **功能**：`isFeatureEnabled(key)`（`useFeatureFlags.ts`）——服务端开关的**唯一**读取入口，由 `loadConfig()` 推入快照；`dock.ts` 里的 `available()` 只用于环境能力。
- **能力**：`terminal/dock.ts` / `proxy/dock.ts` 的 `available()` 读运行时状态。

`App.vue` 把两件事分开汇总：

- `unavailableDockTabs`：每个插件 `available()` 为 false 的 id；
- `featureDisabledDockTabs`：`DOCK_TABS` 里带 `feature` 且 `isFeatureEnabled(feature) === false` 的 id。

两者一起交给 `dockTabs()`；程序化导航过 `switchTab`，它会同时检查隐藏、功能关闭与能力。

清单里的 `feature` / `capability` 字段是**声明**：`feature` 直接驱动渲染过滤（不需要再在 `dock.ts` 里写一遍），`capability` 提醒开发者这个插件依赖环境，并在 `dock.ts` 里实现 `available()`。新增插件若依赖能力，两处都要写；只填清单不会自动门控。

## 5. 预设（profile）

预设是给用户的一步式选择，也是插件可以读取的“环境信号”。它同时决定**显示、顺序和服务端开关**。

| 值 | 含义 | 隐藏 / 关闭 | 顺序 |
|---|---|---|---|
| `developer` | 开发 | 全开 | 默认顺序 |
| `standard` | 标准 | 隐藏 Forge / 终端 / 端口映射，关闭 Forge / 终端 | 开发相关三项挪到设置之前 |
| `minimal` | 极简 | 只留常驻三项，其余（含通知中心）隐藏并关闭 | 常驻三项在前、设置最后，其余按默认顺序 |
| `custom` | 自定义 | 用户手动改过；没有固定语义 | 用户当前顺序 |

默认是 `developer`（所有页签都显示）。

完整顺序与开关表在 `DOCK_PRESET_PLANS`（`useDockPlugins.ts`）里，改预设只改那一处。

### 5.1 预设不是权限

预设只表达“这个用户想把界面调成什么样”，**不能拿它做权限、安全或功能可用性判断**。真正的门控是能力/功能/偏好三轴。

### 5.2 插件怎么读

```ts
import { usePluginProfile } from '@/composables/useDockPlugins'

const { isDeveloper, isStandard, profile } = usePluginProfile()
```

建议：

- `isDeveloper`：显示调试、原始数据、高级开关；
- `isStandard`：隐藏开发相关的高级区块；
- `custom` / `minimal`：回到中性默认，不要猜用户意图。

详见 [05-profile.md](05-profile.md)。

## 6. 顺序规则

- 数组顺序 = 默认顺序，也是“开发”预设的顺序。
- 用户顺序存在 `dockOrder`；`mergeDockOrder(order)` 把它和默认顺序合并。
- 合并规则是**保留默认槽位、采用已存相对顺序**：`order` 里出现过的 id 占它原本在默认顺序里的槽位，并按 `order` 的先后填进去；没出现过的 id 留在原位。
- 因此老数据（升级前 `dockOrder` 只含 9 个可拖项）不会把常驻页签甩到末尾：那 9 个槽位按老顺序排，文件管理仍在第一位。
- 完整列表（管理器拖动后写入的就是完整 14 项）原样复现。

### 6.1 新增页签的位置

新页签不在用户存的顺序里，`mergeDockOrder` 会让它留在默认槽位，而不是追加到末尾。这是有意的：新插件不会因为旧存储而消失，也不会被塞到用户排好的末尾之外。

## 7. 跨插件依赖

插件可以“单独打开”，但不一定“单独有内容”：

| 插件 | 单独打开时 | 依赖 |
|---|---|---|
| 文件浏览 | 最近文件 / 空状态 | 文件管理、历史、聊天提供文件 |
| 分享 | 已分享列表（可能为空） | 文件/会话/会议产生内容 |
| 统计 | 用量数据（可能为空） | 聊天产生用量 |
| Forge | 绑定仓库引导 | 当前项目 |
| 其余 | 自己的空状态 | 不依赖别的插件 |

依赖不等于不能关。关掉上游时，下游显示空状态 + 引导，不要报错、不要白屏。
