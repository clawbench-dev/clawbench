# 踩过的坑

按"加插件时最容易忘"排序。每条都写清**现象**（出问题时你看到什么）和**原因**，这样下次变形了也能认出来。

---

## 前端

### 1. `dockTabs.ts` 必须零 import

**现象**：一批组件的测试在模块加载时就炸，报 `No "FolderOpen" export is defined on the "lucide-vue-next" mock`。

**原因**：`dockTabs.ts` 被 `useWideScreenLayout` 等底层 composable 引用，而那些 composable 被大量组件测试用窄 mock 导入。只要它 import 了图标或插件模块，那些测试的 mock 里就没有对应导出。

**怎么做**：它只放类型和 id 工具函数；插件清单由 `dockPluginRuntime.ts` 装配后通过 `installDockTabIds` 灌进来，方向是 runtime → dockTabs，不能反过来。

### 2. `feature` 打错一个字母 ⇒ 页签永远不消失

**现象**：服务端关了功能，页签还在。

**原因**：前端读不到这个 key 时按"开"处理（首屏不闪的代价）。

**怎么做**：`feature` 必须等于后端 `Section` + `.enabled`。守卫会检查它是否在服务端注册表里，但只在跑集成测试时；本地先自己对一遍。

### 3. 三个开关别混

**现象**：用户说"我明明关了，为什么还在"，或者"我明明开着，为什么灰了"。

**原因**：`feature`（服务端开关）、`capability`（宿主能力）、用户隐藏（`closable`）是三个独立的轴。把"平台不支持"写成 `feature`，用户就会去设置里找一个不存在的开关。

**怎么做**：见 01-frontend.md §7 的表。终端同时有 `feature` 和 `available()`，是唯一需要两个都写的插件。

### 4. 可选面板不要裸 `defineAsyncComponent`

**现象**：设置页/面板每次渲染都重新挂载，输入框失焦、滚动位置丢失。

**原因**：在渲染函数或 computed 里调 `defineAsyncComponent`，每次都返回新的组件身份。

**怎么做**：用 `buildAsyncComponentOptions({ loader })` 在模块加载时包一次（`SettingsCategory.vue` 里 `PLUGIN_PAGES` 就是范例），插件里只写 `load: () => import(...)`。

### 5. 隐藏的页签必须拒绝程序化导航

**现象**：点通知/引用，跳到一个被隐藏的页签，界面空白但地址变了。

**原因**：入口按钮按"功能是否开"过滤，但深链是另一条路径。

**怎么做**：深链 handler 第一行就是 `if (ctx.tabBlocked(id)) return`。

### 6. 新页签不在旧的用户顺序里

**现象**：新插件加上了，老用户看不到（或者排到最后）。

**原因**：用户拖过的顺序存在 `dockOrder` 里，不含新 id。

**怎么做**：`mergeDockOrder` 会把缺失的 id 插到默认位置，不需要写迁移；但**不要**手动改用户存下来的顺序。

### 7. 常驻页签不要写死在模板里

**现象**：加了第四个常驻页签，用户能把它藏掉，然后回不到设置。

**原因**：模板里写死"前三项不可关"。

**怎么做**：常驻列表由 `closable: false` 派生（`DOCK_PERMANENT_TAB_IDS`），守卫会核对两边一致。

### 8. 一个页签只有一个开关

**现象**：设置里有两个开关控制同一件事，一个开一个关。

**原因**：页签的显隐由 `feature` 管，设置页里又放了一个同样的 switch。

**怎么做**：设置页里那个位置只显示状态并链到「功能编排」，不再放第二个开关。

### 9. 模块顶层不要读配置 / 起副作用

**现象**：插件模块一加载就去请求接口，或者在测试里读到上一个用例的残留。

**原因**：`plugin.ts` 是 eager glob 进来的，模块顶层代码在应用启动时就跑。

**怎么做**：需要随可见性起停的东西放 `startBackground()`；一次性读取放 `onEnter()` 或面板组件里。

## 后端

### 10. 接口不在声明的前缀下 ⇒ 静默绕过门控

**现象**：功能关了，某个接口还能调。

**原因**：门控按 `APIPrefixes` 匹配。路由写成了 `/api/foo-extra/x` 而前缀是 `/api/foo/`，就匹配不上。

**怎么做**：新接口一律放在声明的前缀下。守卫 `DeclaredPrefixesOwnRealRoutes` 会检查"声明的前缀有真实路由"，但**查不出**"路由存在却没被任何前缀覆盖"——这条只能自己看。

### 11. 公开路由不门控（这是有意的）

**现象**：功能关了，`/api/share/{token}` 还能打开。

**原因**：公开路由走 `Public`，不套 Gate。关闭时应该由它自己 404，而不是告诉匿名访客"这台服务器关了分享"。

**怎么做**：如果某个公开接口在关闭后必须消失，在 handler 里显式判断，别指望门控。

### 12. 配置字段要加两处

**现象**：设置页保存成功，但值没生效（或者反过来，PATCH 报 400）。

**原因**：`builtinConfigFields`（校验）与插件 `ConfigFields`（声明）是两份。

**怎么做**：两处都加。守卫 `ConfigFieldsMatchHandler` 双向核对。

### 13. `OnDisable` 与 `SwitchEffect` 只能选一个

**现象**：关闭功能时清理跑了两遍（日志重复、第二次对已删数据报错）。

**原因**：handler 对 `SwitchEffect` 两个方向都调，对 `OnDisable` 只在关的方向调；两个都声明就会在"关"时各跑一次。

**怎么做**：单向撤销用 `OnDisable`，双向用 `SwitchEffect`。守卫会红。

### 14. `Start` 必须幂等

**现象**：反复拨开关之后，后台任务跑了两份、日志成对出现。

**原因**：`Start` 可能因为热更新被再次调用（开关没变但配置变了，或者上一次 Stop 没跑完）。

**怎么做**：`Start` 里先判断"已经起了就返回"（终端用 `GetTerminalManager() != nil` 判断）。

### 15. 注册顺序错了不会报错

**现象**：启动日志干净，但没有任何后台任务在跑、没有任何接口被门控。

**原因**：`RegisterAll` 晚于 `startPlugins` / `RegisterRoutes`，注册表是空的，遍历了个寂寞。

**怎么做**：`main.go` 里的顺序是承重的，两条守卫盯着。加启动步骤时别插到 `RegisterAll` 前面。

### 16. 覆盖率按包统计：搬代码必须搬测试

**现象**：代码明明有测试，新包的覆盖率却是 0%。

**原因**：`-coverprofile` 只给被测包自己插桩，别的包跑过不算。

**怎么做**：`git mv` 生产文件时把 `_test.go` 一起搬；新包至少一个测试文件。

### 17. 测试夹具不要手抄生产 DDL

**现象**：测试全绿，上线 `no such column`。

**原因**：夹具是手抄的 schema，比生产多一列/少一列。

**怎么做**：用 `handlertest.FullSchema` + 功能自己的 DDL 常量。已经删掉一个生产不存在的 `scheduled_tasks.description`。

### 18. handler 的测试看不到插件路由

**现象**：在 handler 里给插件接口写测试，永远 404，或者"路由表里没有"。

**原因**：注册表为空时 `RegisterRoutes` 不挂插件路由（否则 handler 得 import 插件包）。

**怎么做**：插件接口的测试放插件包里；handler 里需要完整路由表时先 `registerAllPluginsForTest(t)`。

### 19. 插件不能 import `internal/handler`

**现象**：删掉一个插件目录，handler 编译失败；或者出现 import cycle。

**原因**：handler 是"所有功能的大杂烩"，插件反过来依赖它就成了双向。

**怎么做**：需要 handler 的能力时，先抽到 `httpx` / `filex` / `cfgwrite` / `sharecore` / `stt` / `ws`。这些包就是为此存在的。

### 20. 功能文件里定义 core 也在用的常量

**现象**：把某个功能搬进插件包后，handler 编译失败（`undefined: jsonTotal`）。

**原因**：常量原本顺手写在功能文件里，core 代码也在用。

**怎么做**：共享常量放 `handler/common_consts.go` 这类"无主"位置；功能私有的放自己的 `jsonkeys.go`。搬代码前先 grep 一遍引用。

### 21. `share` 依赖 `live`（单向）

**现象**：删掉 `live` 之后 `share` 编译失败。

**原因**：分享页要把 `/notes`、`/signal` 这些子路径转给会议纪要的处理器。

**怎么做**：这是业务上的真实依赖，不是没做完。删 `live` 时要一并处理 `share` 的转发；删 `share` 不影响 `live`。

## 两边

### 22. `id` 改了等于换了一个功能

**现象**：用户存着的页签顺序失效、服务端配置读不到、旧分享链接指向不存在的功能。

**原因**：`id` 同时是目录名、页签 id、`/api/features` 的键、配置段名、i18n 前缀。

**怎么做**：从第一天就选好。要改名就当成一次迁移（前端顺序、服务端配置、文档三处都要处理）。

### 23. 构建和全量测试不要并发

**现象**：测试读到半成品产物，出现莫名其妙的失败。

**原因**：`npm run build` 会改 `dist/`，Go 测试里有读前端产物的用例。

**怎么做**：先构建，再跑测试；或者用独立的 worktree。
