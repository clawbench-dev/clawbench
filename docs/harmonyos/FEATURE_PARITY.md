# 安卓与鸿蒙功能对齐清单

更新日期：2026-11-09

当前开发版为 `0.2.10 / 210`，沿用包名 `com.clawbench.harmony`，Manifest 保留手机、平板和 `2in1`。0.2.9 关于页文案和区外 DOM 均有回归覆盖；0.2.10 将 Push Kit 说明扩展到默认启动路径，在系统授权前展示并持久化确认，权限拒绝也不跳过说明。新增桥超时、真实 ArkTS 接线、偏好持久化和观察器子树短路测试；非录屏通知与授权流程使用 HarmonyOS 模拟器作为主要验收环境。后台进入 Frozen 后的系统冻结限制保持单独记录。

本清单按 ClawBench Android `v0.136.0` / commit `06a43010` 建立对照基线；鸿蒙 HAP 为 `0.2.10 / 210`。HarmonyOS 客户端已合入上游，但支持仍为实验性：H21 后台通知存在已确认的平台限制，二合一尚未验收，H06–H20 仍需按业务逐项完成。非录屏、可在模拟器重复的通知、权限、导航和常规工作流优先用 HarmonyOS 模拟器验证；需要真实系统冻结调度、硬件编解码或录屏链路的边界单独标注。共享网页的桌面浏览器通过只证明网页本身可用，不替代 ArkWeb 宿主桥验证。

用户验收记录（2026-11-09）：平板端界面、投屏（屏幕共享）、会议由用户确认通过；这里的“会议”指既有入会与音视频流程，不自动覆盖 `v0.136.0` 新增的实时转写、录音拼接和连续语音对话。二合一因缺少设备暂缓，不计为失败。鸿蒙端更新检测等待上游发布包含 HarmonyOS 安装包与版本清单的 release 后再验收；当前上游 `v0.136.0` release 仅有 Android、桌面和服务端资产，未发布 release 时不将无法验证记为代码缺陷。

测试服务器补验（2026-11-09，只读）：`/api/health` 返回 `v0.136.0` / protocol `1`，与本地参考源码一致，服务器已提供新版接口。当前配置 `push_mode=wechat`、`stt.streaming=false`、`meeting.auto_minutes=true`；`stt` 已包含回声消除、降噪、自动增益、频段过滤、语音门限和触发词等新字段；`/api/live-share/notes/sessions` 返回 200 且 `import.available=true`；`/api/terminal/status` 显示 `platform_supported=false`。上游会议听记 WebSocket 在没有流式 STT provider 时会缓冲 PCM 并转为 WAV，再调用非流式 provider；因此 `stt.streaming=false` 本身不能证明会议转写不可用。测试服务器实际 STT provider 与转写结果、鸿蒙端到端流程仍待核验；终端在当前服务器平台不可用，接口存在也不等于鸿蒙端已通过。

0.136.0 的前端/服务端更新会立即增加需要覆盖的语音、会议与触屏工作流，但本地 HAP 并不会因参考源码更新自动刷新：工作台由服务端下发。每次验收记录实际服务端版本与安装包版本；通知和常规原生操作优先使用 HarmonyOS 模拟器完成重复性验证，录屏系统授权与 Frozen 背景调度分别作为平台特定边界。

0.2.3 修复评审发现的凭据恢复、真实宿主桥契约、TLS 诊断与双语反馈，具体构建结果由维护记录保存。此前 0.2.0 至 0.2.2 在 HarmonyOS 7 / API 26 手机模拟器验证过部分文件、分享、剪贴板、选区、通知和媒体流程，以及 SSH / HTTP2 正反向数据转发；SSH 指纹确认和已有映射自动恢复有历史证据，录屏授权后仍挂起。那一阶段没有任何条目通过真机完整验收；之后用户报告的后台消息问题也未因代码回归而解决。单个子场景通过不等于整行功能通过。

0.1.3 阶段已复用安卓登录页，移除额外顶栏，增加全面屏、动态安全区和键盘缩放避让。本轮继续保留这些实现与已有验证记录。

状态约定：未开始、开发中、待验证、通过、受限。不适用项需说明安卓范围依据；“受限”与“通过”分别统计。

| 上游变化 | 鸿蒙现状 | 结论 |
| --- | --- | --- |
