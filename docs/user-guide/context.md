# 上下文、摘要与分叉

> 本文同时适用于桌面端与移动端；两端差异处用 **桌面端** / **移动端** 标注。

长会话如何自动压缩历史、生成摘要，以及分叉与回溯的区别和相关可调项。

## 1. 上下文压缩

对话很长时会自动压缩历史，优先保留全部用户消息，助手条目按预算填充。预算可在设置中调整。

## 2. 摘要

长回复可生成摘要卡片，快速回顾结论；消息显示模式可设为「仅摘要」。

## 3. 分叉与回溯

- **分叉**：从任意一条用户消息创建对话分支，原会话不受影响。分叉会带上压缩后的上下文。适合「换个方向再问」。
- **回溯（Rewind）**：把会话截断到某条消息处并重启 AI 会话。之后的消息被丢弃，适合「刚才答得不对，重来」。

两者都在消息操作条里（**移动端**的操作条含复制、朗读、分叉、回溯、看详情），也支持从会话长按菜单进入。

**移动端**消息操作条对应关系：

| 操作 | 说明 |
|---|---|
| 分叉会话 | 从这条消息开一个新会话，继承之前的上下文 |
| 回溯会话 | 回到这条消息的状态，之后的对话被丢弃 |

## 4. 续接

在已有会话基础上开新会话，标题会带时间戳前缀。

## 5. 相关可调设置

以下设置项同时存在于**桌面端**的会话设置抽屉（点击输入栏底部的**模型**或**模式**打开）与**移动端**的设置 → 聊天中。

| 设置项 | 说明 |
|---|---|
| **消息显示模式** | 混合 / 仅摘要 / 仅原文 |
| **分叉上下文预算** | 分叉时带多少 token 的上下文 |
| **推荐开启 / 上下文条数** | 推荐回复的开关与参考范围 |
| **系统提示间隔** | 每隔多少条消息在上下文开头重新注入系统提示（用于刷新 AI 对项目状态/指令的感知）。间隔太短会增加 token 消耗，太长则 AI 可能遗忘重要指令。设置为 0 则只在会话开始时注入一次。 |

> **消息显示模式**：混合模式（默认）同时展示摘要卡片与原始消息，适合概览与细节兼顾；仅摘要模式只显示 AI 生成的摘要卡片，省界面空间；仅原文模式只展示原始消息，无摘要。切换模式后，新加载的消息按新模式显示，已加载的消息不受影响。

> **分叉上下文预算**：分叉时携带的历史上下文上限，单位为 token 数。值越小，分叉后新会话越轻量但上下文越少；值越大则保留更多历史但 token 消耗增加。默认值适中，修改后建议观察实际效果。

> **推荐回复上下文条数**：生成推荐回复时参考的最近消息轮数。值越大，推荐内容越丰富但计算略慢；值越小推荐越精简。设为 0 则关闭推荐回复。
