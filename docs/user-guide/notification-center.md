# 通知中心

通知中心把**发生过的事**汇聚成一张可回溯的列表：会话完成 / 取消 / 待审批、任务开始 / 完成 / 失败 / 取消、仓库（GitHub / GitLab）动态，都记一行，按时间倒序排列。它回答的问题是「**过去发生过什么**」。

> **它和会话 / 任务 / 仓库的未读角标是两回事。** 角标回答「现在有什么要处理」——是即时、可清零的状态；通知中心回答「发生过什么」——是只追加的历史，**没有已读 / 未读**。所以通知中心没有角标，点开一条通知也不会（也不需要）把它「标为已读」。清掉角标请到对应的地方（打开会话、任务列表的「全部标为已读」等）。

## 打开

通知中心是**左栏的一个页签**（`Inbox` 图标，标题「通知中心」）。

- **宽屏**：在左侧功能栏里点「通知中心」。
- **移动端 / 窄屏**：在底部 Dock 的更多页签里选「通知中心」。

打开后自动加载最新一页。

## 列表

每条通知是一张卡片，从上到下是：

1. **标题行**：类别图标（会话 `Bot` / 任务 `Clock` / 仓库 `GitMerge`）+ 标题 + 时间。
2. **摘要**：最多两行正文（会话回复预览、任务结果摘要、仓库动态描述等）。
3. **元信息行**：事件类型 chip（如「会话已完成」「任务失败」「已合并」）+ 所属项目 + 必要时显示「源已删除」标记。

事件类型覆盖与系统通知完全一致：

| 类别 | 事件类型 |
|---|---|
| **会话** | 已完成、已取消、待审批 |
| **任务** | 任务已开始、已完成、失败、已取消 |
| **仓库** | 已开启、已关闭、已合并、已重新开启、有新评论、流水线已结束 |

## 筛选

列表上方一行三个下拉：

- **项目**：只看某个项目的事件（默认「全部」）。
- **类型**：会话 / 任务 / 仓库（默认「全部」）。
- **时间**：今天 / 近 7 天 / 近 30 天（默认「全部」，即不限时间下界）。

右侧实时显示**当前筛选结果条数**。滚到底部可「加载更多」。

## 点击跳转

点一条通知会跳到它指向的地方——会话、任务执行详情，或仓库的议题 / 合并 / 流水线页签。

**同项目：跳走后能一键返回日志**。通知中心是一个普通页签，但跳转时会记下「你是从日志点过来的」，跳过去之后顶部的返回键、边缘内划（移动端）、Android 硬件返回都会把你送回通知中心——而不是送回你在这个页签**之前**待的地方（那会让人觉得"回错了地方"）。

**跨项目：先弹确认框，不会直接切走**。点其他项目的行会先弹一个确认框（点名目标项目），确认后才切过去。跨项目跳转会拆掉并重建整个项目子树，上一个项目的导航上下文有意丢弃，所以这里不记录返回目标——确认框就是它的替代品（避免留一个指回旧项目的「返回」目标撒谎）。

**其他项目的行会显示项目名**：只有「其他项目」的通知在元信息行右端显示项目名（靠右对齐、与元信息同色）；当前项目的行什么都不显示——**没有名字就是判据**。悬停项目名会提示"点击将切换项目"。

**源已删除时不会跳转**：如果这条通知指向的会话或任务已经被删除，卡片上会显示「源已删除」标记，点击只就地提示、不跳转。这样做是因为打开一个已删除的会话会让界面**静默改道**到别的会话上（比明确告诉你「源没了」更让人困惑）。

> **归档 ≠ 删除**：已归档的会话仍然存在（可以恢复），所以指向它的通知**不**会标「源已删除」，点击照常打开。

## 刷新与清空

- **刷新**：标题栏右侧的刷新按钮，重新拉取当前筛选下的最新列表。
- **清空**：垃圾桶按钮，**清空整条通知历史**（不是只清当前筛选出的部分），需要二次确认，不可撤销。

## 保留期限

通知历史会自动清理：**保留 30 天，且最多 500 条**（双上限）。超出部分由后台定期清理，无需手动维护。

## 常见问题

**为什么我读完会话，这里还显示那条通知？**
因为通知中心**没有已读概念**——它只是一份事件日志，不随「你读没读」变化。会话角标会因你打开会话而清零，通知中心的这条历史记录不会。

**为什么任务 / 仓库的角标数字和通知条数对不上？**
两者统计口径不同：角标数的是「待处理的数量」（会话数 / 执行数 / 去重后的仓库条目数），通知中心数的是「发生过的**事件条数**」。同一条议题上有 3 条新评论，仓库角标算 1、通知中心记 3 条。这是刻意设计，不是 bug。

**通知为什么关掉推送也还在记？**
通知中心是「事实记录」，与推送开关解耦——推送是「尽量实时告诉你」，日志是「无论你看不看都记一笔」。所以你关掉钉钉 / 飞书 / 系统通知后，通知中心仍然完整。
