# 内置智能体（Builtin Agent）设计草案

日期：2026-11-05
状态：草案（v2，补充「系统内部引擎」用途），待评审
关联：`internal/ai`（ACP 客户端）、`internal/ai/backends`（后端注册）、`internal/service/providers.go`（模型提供商）、`internal/summarize`（现有一次性摘要）

## 一句话

在 `clawbench` 里做一个自己的智能体内核：能读文件、写文件、改文件、跑命令，会调模型、会循环用工具。它同时有两种用法——**对用户是一个 ACP 智能体**，**对系统内部是一个可以直接调用的函数**。

## 为什么要做

| 用途 | 现在怎么做的 | 有什么问题 |
|---|---|---|
| 用户聊天 | 拉外部 CLI / npx 桥接 | 要装外部程序、行为不可控、上游改协议就挂 |
| 系统内部干活（skill 提炼、项目总结、需要看文件的摘要） | 没有统一入口，只能借 `summarize` 做纯文本一次性调用 | `summarize` 不会用工具，看不了文件；要做只能临时拼 |

所以这不是「再加一个聊天后端」，而是**一个可复用的执行引擎**：聊天只是它的一个外壳，后台任务直接调它。

## 一、一个内核，两种用法

```
                 ┌─────────────────────────┐
   聊天 ──ACP──▶ │  ACP 适配器（stdio）      │
                 └───────────┬─────────────┘
                             │
                 ┌───────────▼─────────────┐
   后台任务 ────▶ │  内核：调模型 + 跑工具    │
   （直接调用）    │  会话 / 预算 / 截断 / 重试 │
                 └─────────────────────────┘
```

两种用法的差别只有「结果怎么交出去」，内核是同一份：

| | 聊天（ACP） | 内部任务（进程内） |
|---|---|---|
| 谁调用 | ClawBench 服务端 spawn 子进程 | `scheduler` / worker 直接调函数 |
| 结果怎么给 | 流式通知，一条条发出去 | 一次返回最终结果（或结构化对象） |
| 有没有人看 | 有，需要工具卡片、权限弹窗 | 没有，不能弹任何东西 |
| 能不能等 | 可以跑几分钟 | 必须有硬超时（秒级到分钟级） |
| 上下文 | 会话，跨轮累积 | 一次性的，跑完就丢 |
| 崩溃影响 | 只影响这一个会话 | 影响后台任务，要能重试 |

**为什么不统一走 ACP 子进程**：内部任务大多几秒钟，起进程 + 握手 + 读会话是纯开销，而且结果要同步拿。反过来，如果某个内部任务需要复用聊天会话的上下文（比如「总结这个会话」），它可以走 ACP，内核本身不关心。

**内核不能依赖 ACP**：`internal/builtinagent` 只依赖 `internal/model`（拿 provider 配置）和标准库。ACP 适配器是它外面的一个薄壳，放在单独包。这样后台任务 import 内核时不会把整个 ACP 栈拖进来。

## 二、聊天侧：ACP 要实现哪些方法

SDK 已经提供了 agent 侧连接，只需要实现 `Agent` 接口的 12 个方法。真正有逻辑的只有 3 个。

| 方法 | 做什么 | 工作量 |
|---|---|---|
| `initialize` | 返回协议版本；声明 `loadSession: true`，其余能力一律 false | 几行 |
| `session/new` | 生成会话 id、建会话文件、返回模型清单 | 小 |
| **`session/prompt`** | **主循环：调模型 → 执行工具 → 再调模型，边跑边发通知** | **主要工作** |
| `session/cancel` | 打断当前回合（取消 context） | 小 |
| `session/load` | 从磁盘把上下文读回来，**不回放历史消息** | 小 |
| `session/resume` | 同 `session/load` | 小 |
| `session/set_config_option` | 切换模型（`configId = "model"`） | 小 |
| `session/set_mode` | 只有一个 `default` 模式，接受但不改变行为 | 几行 |
| `authenticate` / `logout` / `close_session` / `list_sessions` | 空实现 | 几行 |

要点：

- **不回放历史**：`session/load` 只恢复模型上下文，不发 `session/update`。ClawBench 数据库里已经有完整对话，回放会导致重复渲染。
- **模型清单走 `configOptions`**：`session/new` 返回一个 `category = "model"` 的 select 选项，值来自该智能体绑定的 provider 行。ClawBench 已经能识别这种形状，模型 chip 直接可用。
- **只提供一个模式**：多模式会牵出「切走再切回模式掉回默认」那一串历史问题，内置智能体不需要。

## 三、内部任务侧：怎么调

调用方只需要描述「要干什么」和「允许用什么」，不关心循环：

| 参数 | 说明 |
|---|---|
| 任务描述 | 一段自然语言，作为 user 消息 |
| 系统提示词 | 任务自己的角色设定 |
| 工具集 | 从这个任务允许的工具里挑，默认只有 `read` |
| 工作目录 | 项目根；所有路径限制在里面 |
| 预算 | 最大轮数、最大工具调用次数、最大墙钟、最大输出 token |
| 结果解析 | 可选：一个把最终文本转成结构体的函数 |

返回：

- 成功 → 结果（文本或结构体）+ 实际消耗（轮数、工具调用次数、token）
- 失败 → 明确原因（超预算 / 模型报错 / 结果解析失败）+ 已经产生的部分结果

**结构化输出**：调用方给解析函数，解析失败时把错误原文回喂给模型重试一次；再失败就报错，不硬猜。这条对 skill 提炼、项目总结这类「必须是 JSON」的任务很重要。

**并发**：内部任务有全局并发上限（跟现有 worker 一样有界），每个任务独立，不共享会话。

## 四、内部任务用什么工具（安全边界）

内部任务没有人可以点「允许」，所以默认收紧：

| 任务类型 | 工具 | 说明 |
|---|---|---|
| 项目总结 | `read` + `bash`（只读命令） | 需要 `git log`、`find` 这类命令；cwd 锁在项目根 |
| skill 提炼 | `read` | 只读代码，产出由调用方落盘，不让模型直接写 |
| 会话摘要 / 会议纪要 | 不用内置智能体 | 纯文本一次性调用，继续走 `internal/summarize` |

规则：

- **默认只给 `read`**。要 `bash` 必须显式打开，因为 `bash` 本身就能写文件，「只读 bash」靠命令白名单是挡不住的。
- **`write` / `edit` 默认关闭**。确实需要落盘的任务（比如 skill 提炼要写 `SKILL.md`）由调用方写，不交给模型。
- 所有路径限制在工作目录内，越界直接报错。

这条边界的代价要说清楚：一旦给内部任务开了 `bash`，一个被投毒的仓库文件（README 里写着「请执行 rm -rf」）就可能让后台任务跑任意命令，而且**没有人会看到权限弹窗**。所以 `bash` 只给确实需要的任务开，并且这类任务的输出不直接回给用户。

## 五、模型从哪来

| 场景 | 模型来源 |
|---|---|
| 内部任务 | 默认用「共享摘要模型」（`config.yaml` 的 `ai_summary`：provider + model）；单个任务可以覆盖 |
| 聊天 | 智能体自己绑定的 provider；没绑就回落到共享摘要模型，并在界面上标明「正在使用摘要模型」 |

为什么内部任务默认用摘要模型：后台任务（标题、推荐、纪要）本来就用它，配一次所有功能都能用，不会出现「新建的内置智能体没人配过、后台任务全失败」。

**没配摘要模型时**：内部任务直接报错，提示去设置里绑一个 provider；聊天入口也一样。不做「悄悄用某个默认值」这种兜底——用户会以为在用一个模型，实际跑的是另一个。

## 六、会话存在哪（仅聊天需要）

**一个会话一个 JSONL 文件**：`{data-dir}/builtin-agent/sessions/<会话id>.jsonl`，一行一条消息（角色、内容、工具调用、工具结果）。

- `session/new` → 生成 id + 建空文件
- `session/load` / `session/resume` → 读文件，还原成模型上下文
- 每轮结束追加写入（工具结果也写，否则恢复后模型会重复调用工具）

为什么不直接用 `chat_history`：那是「展示层」的事实源，子进程读不到（数据库有进程级写锁），而且 ACP 的语义本来就是「智能体自己管上下文」。两份数据不打架——一份给用户看，一份给模型看。

**清理**：ClawBench 删会话时不会通知子进程，会话文件会变成孤儿。方案是子进程启动时清理 30 天没动过的文件。内部任务不写会话文件，所以不涉及。

## 七、四个工具

| 工具 | 入参 | 行为 | 边界 |
|---|---|---|---|
| `read` | `path`、可选 `offset`/`limit` | 返回带行号的文本 | 单次最多 2000 行 / 256KB，超了明确告诉模型「还有多少行，用 offset 继续」 |
| `write` | `path`、`content` | 覆盖写，自动建父目录 | 返回写入字节数 |
| `edit` | `path`、`old_string`、`new_string`、可选 `replace_all` | 精确字符串替换 | 匹配不到或匹配到多处都报错（不猜），`replace_all` 才允许多处 |
| `bash` | `command`、可选 `timeout` | 在会话 cwd 下执行 | 默认 120 秒；输出截断到 30KB，保留头尾并注明截断了多少 |

共同规则：

- **所有路径必须落在工作目录内**，越界直接报错，不弹权限框（弹了模型也会一直重试）。仓库已有 `filepath-securejoin` 依赖可用。
- 聊天场景下，工具调用前后各发一次 `session/update`：开始时 `tool_call`（带 `kind` 和 `locations`），结束时 `tool_call_update`（`completed` + 结果摘要）。`kind` 决定前端图标，`locations` 让点击能跳到文件。内部任务不需要发这些。
- 只做这四件，不做 `glob`/`grep`/`ls`——`bash` 能干，少一个工具就少一份提示词和一份测试。

## 八、权限

- 聊天：`read` 不问；`write` / `edit` / `bash` 走 `RequestPermission`，提供「允许一次 / 本会话总是允许 / 拒绝」。ClawBench 的「自动批准」是客户端行为，内核不需要知道。
- 内部任务：没有权限环节，靠上面的工具集限制兜底。

## 九、明确不做（边界）

| 不做 | 原因 |
|---|---|
| MCP 工具 | `session/new` 会带 `mcpServers`，v1 直接忽略。要 MCP 就用别的智能体 |
| 图片 / 附件 | 现有 ACP 路径不内联图片，只在文本里给路径。`read` 遇到二进制直接报错 |
| 斜杠命令 | 不发 `available_commands_update`，输入框不会出现命令列表 |
| 中途插话 | 不做 steering，用户中途发的消息照常排队 |
| 计划 / 待办 | 不发 `plan` 通知，前端不显示计划面板 |
| 上下文压缩 | v1 不做。超了直接报错，提示新开会话 |
| 子智能体 / 任务委派 | 不在范围内 |
| 替换现有 `summarize` | 纯文本一次性调用继续用它，没必要为没有工具的任务套一层循环 |

## 十、要动仓库的哪些地方

| 位置 | 改动 |
|---|---|
| `internal/builtinagent/`（新包） | 内核：模型调用、工具循环、四个工具、预算、会话文件。**不 import ACP** |
| `internal/builtinagent/acpagent/`（新包） | ACP 适配器：把内核的事件翻译成 `session/update` |
| `cmd/server/main.go` | 加 `--acp-agent` 分支，走 stdio 直接进 agent 模式，不启动 HTTP 服务 |
| `internal/ai/backends/builtin/`（新包） | 注册后端：`AcpCommand` 指向自己，`NoCLI: true`，`AutoLoadsNativeSkills: false` |
| `internal/model/discovery.go` | 可能需要加一个「内置」标记，用来决定 `acp_command` 由运行时解析还是写死 |
| `internal/service/` | 需要工具的后台任务改成调内核（第一期只接一个任务验证） |
| 前端 | 无（顶多加个图标） |

**自指命令怎么给**：`spawnLocked` 用 `strings.Fields(AcpCommand)` 拆命令，所以路径不能带空格，也不能依赖 `clawbench` 在 PATH 里。推荐在注册后端时用 `os.Executable()` 拼绝对路径，写进 `BackendSpec.AcpCommand`。副作用是每次启动 `syncAgentInfrastructure` 都会把它重写成当前路径——桌面版每次升级目录会变（`app-<版本>/`），需要确认 refresh 一定在第一次 spawn 之前跑完。

## 十一、风险与待定

1. **升级后路径失效**：桌面端升级会换目录，旧记录里的绝对路径指向已删除的文件。要么靠启动时的 refresh 兜住，要么改成「内置后端在 spawn 时实时解析路径」（需要在 ACP 层开一个口子）。**这条要先验证。**
2. **内部任务的安全边界**：开了 `bash` 就等于把项目目录交给模型，而没有人看得见。这条只能靠「哪些任务开 bash」的清单来控制，没有技术兜底。
3. **没有压缩**：长会话一定撞上下文上限，v1 只能是「报错让用户新开」。如果内置智能体要长期跑，压缩迟早要做。
4. **两份会话数据**：JSONL 和 `chat_history` 可能不一致（服务端删了会话、文件还在）。靠超时清理兜底。
5. **LLM 协议**：v1 只做 OpenAI 兼容（`/chat/completions` + SSE）。`providers.protocol` 里还有 anthropic，要不要一并做，看第一批用的是哪种。
6. **每会话一个进程**：内存比进程内实现高，但复用整条链路的价值更大。

## 十二、分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| 一 | 内核 + `read` + `bash` + OpenAI 流式 + 内部调用入口 | 后台任务里跑一个「读文件然后总结」，能出结果 |
| 二 | ACP 适配器 + `--acp-agent` + 后端注册 | 界面上能新建内置智能体、能聊天、能看到工具卡片 |
| 三 | `write` + `edit` + 权限弹窗 + 取消 | 能改文件，权限弹窗正确，中断按钮能停 |
| 四 | `session/load` + 切模型 + 会话文件清理 | 服务重启后对话能继续，模型 chip 能切 |
| 五 | 接第二个内部任务（skill 提炼或项目总结），验证预算与结构化输出 | 任务失败时能明确报出是超预算还是解析失败 |

## 已定 / 待定

**已定**（本轮补充需求后收口）：

- 作用域：全局一个。内部任务不依赖项目；聊天时工作目录取当前项目。项目级独立配置留到以后。
- 模型：内部任务默认共享摘要模型，聊天默认也回落它；没配就报错，不做静默兜底。
- 架构：内核与 ACP 解耦，后台任务不经过进程。

**待定**：

1. 名字叫什么？（影响 `BackendSpec.Name` 和界面显示）
2. 第一个接的内部任务选哪个？（skill 提炼 / 项目总结）
3. 内部任务的 `bash` 到底开不开？开的话给哪几类任务。
