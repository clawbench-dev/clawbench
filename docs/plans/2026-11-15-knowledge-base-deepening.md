# 知识库深化设计（Knowledge Base Deepening）

日期：2026-11-15
状态：四批全部实现并通过端到端验证

## 背景

知识库现在能建库、加文件、自动解析切段、关键词 + 语义检索、聊天自动注入并在回答下方标引用。链路是通的，但用户打开面板后最常问的三个问题都答不了：

1. **我加的东西进去了吗？** 看不到文件被解析成了什么，失败只有一个红色标记，原因直接显示英文原始报错。
2. **它到底能不能被搜到？** 搜索框只在选中某个库之后才出现，必须回车，结果卡片不能点开。
3. **AI 用的是哪一版？** 源文件改了不能更新，重建只重读当初复制进来的副本；聊天里的引用条点不回原文。

另有一部分「单薄」是假象：后端已经做了文档详情、索引统计、库改名、语义检索模式，前端没接。所以第一批改动不需要新能力，只要把线接上。

本设计的目标不是把功能列表堆长，而是把「加进去 → 看得见 → 搜得到 → 用得上 → 不过期」这条路补完整。

## 决策汇总

| 维度 | 决策 |
|---|---|
| 产品定位 | 从「文件柜」改为「可验证、可用上的资料库」 |
| 第一批范围 | 只做前端能接通的闭环，不改数据表；列表接口补健康计数、详情接口补片段窗口 |
| 文档详情形态 | 抽屉：窄屏底部抽屉、宽屏居中卡片（同一个 `BottomSheet` 自动切换）；**不做第三栏** |
| 搜索位置 | 提到面板第一层常驻；默认「全部」，选中库后默认「当前库」 |
| 搜索触发 | 输入即搜走关键词；回车走混合 |
| 项目切换 | 清空选中并重载；按 `resetProjectState()` 的既有约定登记 |
| 失败原因 | 后端存原因码，前端出人话；旧数据回落到原文 |
| 索引完成通知 | 一批只发一条，不按文件发 |
| 库健康度 | 列表徽章 + 详情健康行；计数由列表接口下发 |
| 组织模型 | 单层文件 + 标签（后续）；**不做文件夹树** |
| 采集入口 | 文件管理器、聊天、会议纪要、拖拽，全部复用现有选择器与引用机制 |
| 打开原始文件 | 本轮不做。知识库看到的应当是索引的那一份副本 |

## 现状盘点

| 能力域 | 已有 | 缺口 |
|---|---|---|
| 采集 | 面板内选文件、选文件夹、上传 | 文件管理器右键、聊天存笔记、粘贴文本/URL、拖拽 |
| 组织 | 库（全局/项目）、单层文件列表 | 改名改说明、标签、批量、跨库移动、排序筛选 |
| 索引 | 自动解析切段、双索引、单文件/整库重建 | 源文件更新、进度可见、失败可排查、完成通知 |
| 检索 | 混合/关键词、全库/单库、命中高亮 | 输入即搜、结果可点、真实总数、语义降级提示 |
| 消费 | 聊天自动注入 + 折叠引用条 | 引用回原文、手动指定文档提问、片段引用到聊天 |
| 治理 | 设置页统计、整库重建 | 库级健康度、过期/重复检测、占用清理 |

### 代码证据：后端有、前端没接

- `GET /api/kb/documents?id=` 返回文档详情 + 前 20 个片段（`internal/handler/kb.go:266`），前端从未调用。
- `/api/kb/status` 的 `stats` 与 `vector_enabled` 取了但面板不展示（`web/src/composables/useKnowledgeBase.ts:117`）。
- PATCH 支持改 `name` / `description`，UI 只用了 `auto_inject`（`web/src/composables/useKnowledgeBase.ts:226`）。
- 后端支持 `mode: "vector"`，UI 只有「混合 / 关键词」。
- 文档的 `source_path` 存了但不显示，同名文件无法区分。
- 搜索结果带 `document_id` / `chunk_id`，卡片没有跳转；引用条带 `documentId`，也不可点（`web/src/components/chat/ChatKBRefs.vue:20`）。

### 代码证据：确实没有

- **切项目不刷新**：`TabPanel` 用 `v-show` 保活，面板只监听 `active`（`web/src/components/kb/KnowledgePanel.vue:521`）。切项目后列表仍是旧项目的库，此时添加文件会拿旧库 id 打新项目，返回 403。项目作用域缓存按约定应在 `resetProjectState()`（`web/src/stores/app.ts:329`）里清，知识库漏了。
- **源文件改了不能更新**：重建只重解析已存副本（`internal/kb/kb.go:424`），重复添加同内容被 409 挡。
- **索引完成无通知**：`internal/kb` 内没有任何通知写入。
- **失败原因不可读**：索引失败时直接把 `err.Error()` 存进 `doc.error`（`internal/kb/indexer.go:125`），面板原样显示（`web/src/components/kb/KnowledgePanel.vue:246`）。
- **搜索入口在详情里**：搜索行位于 `v-if="selected"` 之内（`web/src/components/kb/KnowledgePanel.vue:141`）。
- **结果数不是总数**：`Total` 取 `len(hits)`（`internal/kb/search.go:150`），而 `hits` 默认上限 10。
- **语义检索静默降级**：嵌入不可用或向量表为空时直接退化为关键词检索（`internal/kb/search.go:118`），界面仍显示「混合」。
- **搜索无乱序保护**：`runSearch` 没有请求序号（`web/src/composables/useKnowledgeBase.ts:291`），慢响应会盖掉新结果。
- **采集入口单一**：文件管理器右键只有「附到聊天」（`web/src/components/file/FileManagerContent.vue:491`）。

## 第一批：补闭环（10 项，基本纯前端）

目标：加进去的东西看得见、失败看得懂、搜得到也点得进去、改得动、不出错、不骗人。

### 1. 文档详情抽屉

- **交互**：点文件行打开抽屉。顶部是标题、状态、大小、原路径；中部是「解析出的内容」——前 20 个片段，每段带页码/行号定位；失败时整块替换为原因、建议与「重建」按钮。
- **接口**：`GET /api/kb/documents?id=`（已有）。命中片段可能不在前 20 段内，需补一个可选参数 `chunk_id`，返回该段前后各若干段（见第 7 项）。
- **复用**：`BottomSheet`（窄屏底部抽屉、宽屏居中卡片自动切换），不新写外壳。
- **验收**：失败文件能在两次点击内看到原因；片段数与列表一致；抽屉内重建后状态原地变化。

### 2. 库改名 / 改说明

- **交互**：库标题旁的编辑入口，或库行菜单；弹窗复用 `ModalDialog`。
- **接口**：`PATCH /api/kb/collections?id=`（已有）。
- **边界**：历史消息里的引用条是快照，改名不会回溯，需要在文案上避免误导。
- **验收**：改名后列表、下拉、新建文档的选择器都显示新名。

### 3. 切项目刷新（同时修 403）

- **现状**：面板实例常驻，只监听 `active`。
- **方案**：监听 `store.state.projectRoot`，变化时清空选中、文档、搜索结果并重载；或按仓库既有做法在 `resetProjectState()` 里注册重置钩子（参考 `resetSkillsCache`）。
- **验收**：切项目后列表立即变；旧项目的库不出现；添加文件不报 403。

### 4. 选中库的健康行

- **交互**：库标题下加一行 `12 个文件 · 1 失败 · 2 索引中 · 仅关键词`；点「1 失败」筛出失败文件，点「2 索引中」筛出处理中的文件。
- **数据**：由当前 `documents` 现算，纯前端。
- **验收**：计数与列表一致；筛完能一键清空。

### 5. 库列表健康徽章

- **现状**：`Collection` 只有 `doc_count`。
- **方案**：列表接口补 `failed_count` / `pending_count`（子查询），库行显示小徽章；没有问题的库不显示任何东西。
- **验收**：不进库就能看出哪个库有问题；计数随刷新更新。

### 6. 搜索提到面板第一层

- **交互**：面板头部下常驻搜索框。范围默认「全部」，选中库后默认「当前库」，可手动切回；窄屏在库列表层也能直接搜。
- **复用**：`SearchBar` / `SearchInput`。
- **验收**：不选库也能搜；切换范围结果正确；返回列表不清空查询词（除非用户主动清）。

### 7. 搜索结果可点，落到那一段

- **交互**：点结果打开文档详情，滚到命中片段并高亮。
- **数据**：命中可能落在第 20 段之后，详情接口需支持按 `chunk_id` 取该段前后若干段；没有这个参数时明确提示「该片段在第 N 段」，不能假装定位成功。
- **验收**：任意结果点开都能看到命中段；深文档也能定位。

### 8. 语义降级要说出来

- **数据**：`vector_enabled`（是否配置了嵌入）与 `stats.embedded_chunks / stats.chunks`（是否嵌完）。
- **交互**：搜索框旁一行安静的小字：「当前仅关键词检索（未配置语义索引）」或「语义索引进行中 120 / 500」。
- **验收**：关掉嵌入配置时提示出现；配好并嵌完后消失。

### 9. 失败原因说人话

- **现状**：存的是 `err.Error()` 原文（英文）。
- **方案**：索引失败时存稳定的原因码（复用 `kbReasonKey` 那套 reason），前端按码出文案与建议；未知码回落原文。旧数据不迁移，直接回落显示原文。
- **验收**：扫描件 PDF 显示「没有可提取的文字，可能是扫描件」，而不是英文报错。

### 10. 引用条点回原文

- **交互**：点引用条目 → 切到知识库页签 → 打开该文档 → 定位该段。
- **前提**：需要一条跨面板跳转通道（`App.vue` 已有程序化切页签与 `switchLeftTab`，但要注意窄屏与项目切换）。
- **边界**：文档已删除时提示「原文已删除」，不跳转。
- **验收**：从聊天点回原文；删掉文档后点击有提示且不白屏。

## 第二批：防过期、撑规模（8 项）

### 11. 用原文件更新

- **交互**：文档行菜单「用原文件更新」；源文件不存在时置灰并说明。
- **后端**：重新读 `source_path` → 校验 → 复制覆盖副本 → 比对内容指纹 → 变了才重建索引；没变只提示「已是最新」。
- **边界**：源文件被移动/删除要明确报错，不静默。
- **验收**：改源文件后更新，片段变化；未改时提示已是最新。

### 12. 索引进度与完成通知

- **面板**：处理中数量 + 可选进度条。
- **通知**：一批导入结束发一条（成功 N / 失败 M），走通知中心；单文件不单独发，避免刷屏。
- **验收**：离开面板后能收到；失败数正确。

### 13. 批量选择

- **交互**：长按或勾选进入多选，`ActionBar` 切换为「删除 / 重建 / 移动 / 取消」。
- **范围**：第一批只做删除与重建；移动需要新端点（改库、重算项目归属、移动副本、重建索引），单独排期。
- **验收**：选 10 个删除只弹一次确认。

### 14. 文档列表筛选与排序

- **筛选**：状态（失败 / 处理中 / 仅关键词）、类型、时间。
- **排序**：默认「最近添加」，可切「名称」。
- **验收**：筛失败只剩失败；排序切换立即生效。

### 15. 轮询与规模

- **现状**：每 2.5 秒整表重载，500 个文件时开销明显。
- **方案**：只刷新处理中的行；超过 200 条分页或虚拟滚动。
- **验收**：500 文件时轮询不卡、滚动不跳。

### 16. 结果数说真话

- **方案**：先改文案为「前 10 条」；需要真实总数时再加 count 查询。
- **验收**：文案与行为一致。

### 17. 搜索防乱序

- **方案**：加请求序号，只采纳最后一次响应。
- **验收**：快速连搜两次，结果对应最后一次输入。

### 18. 导入前预览

- **交互**：选目录后先 dry-run，给出「将加入 42 个、跳过 8 个（类型不支持）、重复 3 个」，确认后再导入。
- **后端**：导入接口加 `dry_run`。
- **验收**：500 个文件先看到数字再决定。

| # | 优化点 | 说明 |

## 明确不做

- **库内文件夹树**：手机上会压垮操作，标签足够。
- **OCR / 音视频转写**：规格已明确不做。
- **多人权限与协作**：单人产品。
- **向量模型选择界面**：复用会话搜索的嵌入配置，多一个入口只会多一处不一致。
- **文档内全文搜索**：先把片段跳转做好。
- **知识图谱**：投入大、验证难。
- **打开原始文件**：本轮只做详情抽屉。知识库看到的应当是索引的那一份副本；源文件可能已移动或删除。

## 风险与取舍

- **库健康徽章需要列表接口加计数**：子查询会随库数量增长，但库通常不到 20 个，可接受。若后续变慢，再改成单次聚合查询。
- **索引完成通知可能打扰**：按批发送；只有存在失败时才提升提醒级别。
- **搜索提层改变默认范围**：老用户习惯先选库，用「选中库后默认当前库」缓解，不做引导弹窗。
- **引用条跳转要碰 `App.vue`**：注意窄屏页签与项目切换两条路径，避免跳过去看到空面板。
- **详情抽屉与返回手势**：复用 `BottomSheet` 的既有返回处理，不额外注册。
- **改名不回溯历史引用**：引用条是消息快照，明确写进文案，避免用户以为改名后历史也变。

## 实现约束

- 新增或修改 `/api/` 端点必须同步 `internal/api/openapi.yaml`（字段名从 handler 抄）。
- 新增界面复用共享控件：`ActionBar`、`BottomSheet` / `ModalDialog`、`SearchBar`、`SplitView`、`EmptyState`，不另搭简化版。
- 日志用 `appLog`，禁止裸 `console.*`。
- 每个功能点带单元测试；跨组件流程（加文件 → 详情 → 搜索 → 跳转）补一条 E2E。
- 纯新增字段属于兼容变更，不抬客户端协议号。

## 验收标准（整体）

- 新用户从空库到「聊天里用上」不超过三步。
- 任一失败文件都能在两次点击内看到原因。
- 任一搜索结果都能跳到原文片段。
- 切项目后不会看到上一个项目的库。
- 源文件更新后不需要删库重加。
- 语义索引不可用时，界面明确说明，而不是继续显示「混合」。

## 建议的实施顺序

1. 第 3 项（切项目刷新）——先修错误，避免用户踩 403。
2. 第 1 项（详情抽屉）——它是第 7、9、10 项的地基。
3. 第 6、7 项（搜索提层 + 结果可点）——把「找得到」补完。
4. 第 9、4、5 项（失败说人话 + 健康度）——把「看得懂」补完。
5. 第 8、10、2 项（降级提示 + 引用回跳 + 改名）——收尾。
6. 第二批从第 11 项（源文件更新）开始，它是知识库可信度的根。

## 实施记录（第一批，2026-11-15）

已落地：

1. 文档详情抽屉（`KBDocumentDrawer.vue`）：解析片段、定位、原路径、失败原因、重建/删除；命中片段高亮。
2. 库改名 / 改说明（创建与编辑共用同一个表单，归属仍只读）。
3. 切项目刷新（监听 `projectRoot`，清空选中并重载；同时关掉打开的抽屉）。
4. 选中库健康行 + 点击筛选（全部 / 失败 / 处理中 / 仅关键词）。
5. 库列表健康徽章：`ListCollections` / `GetCollection` 补 `failed_count`、`pending_count`（`pending` + `extracting` 合并）。
6. 搜索提到面板第一层；未选库默认「全部」，选中库默认「当前库」。
7. 搜索结果可点：打开文档并定位到命中片段（详情接口支持 `chunk_id`，返回前后各 5 段）。
8. 语义索引降级提示（未配置 / 嵌入进度）。
9. 失败原因本地化：索引器写稳定原因码，前端按码出文案，未知原因回落原文。
10. 聊天引用可跳回知识库：新增 `chunkId` 到 `kbRefs` 与 `ai.KBRef`，引用条增加「在知识库中查看」。

两处与原计划的偏差：

**取舍说明**：

- 标签用单列逗号分隔，不建标签表。当前是单用户本地库，标签只用于显示与筛选；建表会引入标签重命名、孤儿清理、多对多查询，收益不匹配。
- 引用统计只记「自动检索带进对话」，不记手动搜索。手动搜索是浏览行为，拿它当「这个库有用」的证据会失真。
- 撤销是「从原文件重新加入」而不是回收站。真正的回收站要保留副本、加删除标记、写清理任务，还会影响删库/删项目的路径；当前确认框 + 原文件恢复已经覆盖常见误删。
