# ask-question 改为标签内原生 Markdown

日期：2026-09-19
状态：已确认，待实施

## 背景与动机

当前 `<ask-question>` 标签内部是自定义 XML（`<item>` / `<header>` / `<question>` /
`<option>` / `<multi-select>`）。问题：

- **模型经常写不规范**。真实数据里 24% 的载荷有未闭合的 `<item>`/`<option>`，
  12% 把标签写成属性（`<option value="A">`），还有复数 `<options>` 包裹、
  裸文本 `<option>`、损坏的闭合标签（`</` + 全角竖线 + `DSML` 等）。
- 自定义 XML 对模型而言是**非训练分布**的格式，写错是常态而非异常。
- 这些畸形最终都要靠容错解析器去猜，猜错就丢内容。

Markdown 是模型的母语格式，列表语法尤其稳定。把标签内部换成原生 Markdown，
畸形率会显著下降，且**失败时可以优雅降级**——把标签内文字交给 Markdown
渲染器，用户看到的是正常排版的文字，而不是一坨 XML。

## 目标格式

标签名不变，无属性、无 JSON。**一个标签一个问题**，多个问题用多个标签。

### 单选

```
<ask-question>
**方案选择**
你更倾向哪种实现方式？
- 方案 A — 快但不够安全
- 方案 B — 安全但慢
</ask-question>
```

### 多选

```
<ask-question>
**需要启用哪些**
- [ ] 语法高亮
- [ ] 自动换行
</ask-question>
```

### 规则

| 元素 | 语法 | 说明 |
|---|---|---|
| header | `**加粗**` 独立成行 | 可选，取第一个 |
| question | 其余非列表行 | 拼接；可选 |
| option | `- 选项` 或 `* 选项` | 描述用 ` — `（em dash）或 ` - ` 分隔 |
| 多选 | `- [ ] 选项` / `- [x] 选项` | 任一复选框出现即整个问题为多选 |
| 描述 | `- 标签 — 描述` | 可选 |

- **多选判定**：出现 `- [ ]` 或 `- [x]` 即为多选，不需要额外标记。
- **单选判定**：普通无序列表。
- 有序列表（`1.`）同样接受，视为单选选项。

## 解析与失败处理

解析顺序：

1. 先按**新 Markdown 格式**解析。
2. 失败则按**旧 XML 格式**解析（历史会话兼容，必须保留，否则旧卡片会变成裸 XML）。
3. 都不成 → **解析失败**。

**失败处理（本次决策的反转）**：

- 旧契约：不可解析时**原样保留整个标签**（含 XML 尖括号一起显示）。
- 新契约：不可解析时**剥离标签，把标签内文字交给 Markdown 渲染器**。

两者都不丢文字。新的更干净：失败时自然退化成普通 Markdown，不再向用户
暴露原始 XML。代价是失败时看不到标签边界，排查格式问题需要看日志。

实现要点：`Strip` 对未解析的 span 不再整段跳过，而是输出其**内部文本**
（去掉开闭标签本身）；前端把该文本并入 markdown 渲染。

## 测试策略

- 新格式：单选、多选、带描述、有序列表、无 header、多问题多标签。
- 失败回退：畸形 md（无列表）、空标签、纯 JSON → 剥离标签、内部文本可见。
- 兼容：旧 XML 全部既有用例继续通过。
- parity：Go 与 TS 由同一语料双向固定。
- 真实数据回归：645 个历史文本块的解析/剥离字节数不得劣化。

## 不做的事

- 不改标签名（避免前后端与历史数据双重迁移）。
- 不引入 JSON 载荷（维持 d189374e1 的决定）。
- 不加标签属性（属性是模型最容易写错的部分）。

## 追加：异常格式适应性（2026-09-19 第二轮）

对 645 个真实文本块（464 个 span）实测后，针对**实际出现**的畸形放宽解析。
每条放宽都配了反向守卫，避免把普通正文误判成列表。

### 标记（列表符号）

| 形式 | 例 | 说明 |
|---|---|---|
| 破折号后无空格 | `-甲` | 真实出现 5 次；此前整个载荷解析失败 |
| 全角连字符 | `－ 甲` | |
| 加号 | `+ 甲` | |
| CJK 顿号序号 | `1、甲` | |
| CJK 数字序号 | `一、甲` | |
| 括号序号 | `1) 甲` | |
| 全角空格缩进 | `　- 甲` | U+3000 |

守卫：`*` 后必须跟空格（`**粗**`/`*斜*` 不是列表）；`-`/`+`/`－` 后不能是数字或连字符（`-5`、`---` 不是列表）；`1.`/`1)` 后必须跟空格（`1.5` 不是列表）。

### 复选框

`[ ]` / `[x]` / `[X]` / `［ ］` / `【 】` / `[]甲`（括号内无空格、括号后无空格）。

### 标题

`**加粗**` / `__加粗__` / `# 标题` ~ `###### 标题`。标题必须出现在选项之前，否则视为正文（选项里的加粗是选项标签）。

### 描述分隔

` — `（em dash，优先）/ ` – `（en dash）/ ` - `（连字符）。

### JSON 恢复（本轮最大收益）

真实数据里 **7 个**载荷是 JSON 而非 Markdown。JSON 不是文档化格式（系统提示词要求 Markdown，且 `d189374e1` 曾刻意移除支持），但**直接丢弃会损失可读的问题**，因此改为「尽力恢复」：

- 接受 `{"questions":[...]}` 与裸数组 `[{...}]`，复用 `NormalizeInput` 的键名同义词与畸形容忍。
- **未转义引号修复**：真实样本里模型在 JSON 字符串值内写了未转义的排版引号（`"临时分裂"`），标准 `json.Unmarshal` 会在第一个引号处整体失败。修复规则：只有当引号后第一个非空白字符是 `:`、`,`、`}`、`]` 时才算闭合引号，否则视为内部文本并转义。
- 恢复失败则回落到 Markdown 渲染，因此失败零代价。

### 实测结果

| 指标 | 本轮前 | 本轮后 |
|---|---|---|
| 解析成功率 | 80.2% (372/464) | **81.2% (377/464)** |
| 越界 span | 0 | 0 |
| 未解释的删除字节 | 0 | 0 |

未解析的 87 个 span 中，绝大多数是**正文里提到标签**（内联代码或讨论格式），本就不该成卡片。
