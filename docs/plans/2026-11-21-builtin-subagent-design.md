# 内置智能体：子智能体（一期）设计

日期：2026-11-21
状态：方案（未实现）
关联：`docs/plans/2026-11-16-builtin-agent-design.md`（内置智能体内核）、`internal/agentcore`、`internal/ai/backends/builtin`

## 一句话

内置智能体可以调用一个 `task` 工具，把一块独立任务交给临时子智能体去跑。子智能体有全新的上下文、与父相同或更窄的权限，跑完把报告交回来。界面沿用现有的「子内容折叠在卡片里」渲染，父的上下文只多一份报告。

## 目标

- **隔离**：父的模型上下文只多一份报告，不多子读过的几十个文件、几百行搜索输出。
- **不提权**：子只能做父本来就能做的事；递归到顶就不给 `task` 工具。
- **不失控**：父子共用一本预算账，子智能体数量和递归深度都有硬上限。
- **不污染父回合**：子的结束、压缩、报错不能当成父的结束或父的压缩。

## 一期不做

| 不做 | 原因 |
|---|---|
| 并行 / 异步 spawn | 现在工具本来就是串行执行，先不引入并发状态 |
| 子智能体类型（explore / plan） | 一期只有一种「通用子智能体」 |
| 子智能体专用模型 | 先用父的模型，把主路径跑通 |
| 团队面板里的成员 | 那是群聊 / 团队的另一套模型，别混 |
| 把「给模型看」和「给界面看」的输出分开 | 接受存储和抽屉里的重复；真正要防的是下一轮上下文重复（见「历史重放」） |

## 方案

### 1. 工具形态

一个同步的 `task` 工具：

```json
{
  "description": "查找支付相关代码",
  "prompt": "在 /repo 里搜索所有与支付相关的文件……最后给我一份清单：文件路径 + 一句话说明。"
}
```

- `description`：3–6 个词的短标题，卡片上显示。
- `prompt`：完整任务说明。**子看不到父的对话**，父必须把背景、范围、期望产出写全。
- 工具描述要写清楚什么时候用：独立、会产生大量中间输出、值得隔离的工作（大范围搜索、多文件调查）；什么时候不用：一次 `read` / `grep` 就能做完的事。

前端已经认识 `task` 这个名字：有 Agent 图标，也有 `{description, prompt}` 的专用卡片（`web/src/utils/renderToolDetail.ts` 的 `Task` 渲染器）。**一期前端不需要改代码。**

### 2. 子智能体看到什么

| 内容 | 取值 |
|---|---|
| 系统提示 | 父的 `SystemPrompt`（含项目规则、技能、自定义指令）+ 一段 `<role>` 子智能体说明 |
| 对话 | 只有 `prompt` 一条用户消息；**不回放父的历史** |
| 工具 | 与父相同的有效策略（已经按 read / write / full 收窄过）；到深度上限时不含 `task` |
| 工作目录 | 与父相同 |
| 模型 / 输出上限 / 上下文窗口 / 压缩 | 与父相同 |

`<role>` 子智能体说明要写三件事：

1. 你是子智能体，只负责一个任务；你没有用户，不要提问、不要等确认。
2. 有歧义就说明假设并继续，不要停下来问。
3. 结束时给一份简短报告：做了什么、发现了什么（带文件路径）、父必须知道的遗留问题；不要复述任务。

实现上：子的 `History` / `HistoryMessageIDs` / `PriorSummary` 都为空；`Timeout` 为 0（靠父的 ctx 统一限时）；`SessionID` 与父不同（或为空），避免两份不同的对话共用同一个前缀缓存键。

### 3. 权限

- 子策略 = 父当前的 `Spec.Policy`，只能一样或更窄。子不能再调 `ForMode` 放宽。
- `task` 本身不是新的能力位：父只要有文件或命令能力，就可以派生；一个工具都没有的智能体不注册 `task`（子也只能干聊，没有意义）。
- 深度到顶时不注册 `task`，用「工具不存在」表达禁止，而不是「调用被拒」——这和现有的安全模型一致（不允许的工具压根不给模型看见）。

### 4. 递归与数量

| 常量 | 取值 | 含义 |
|---|---|---|
| `maxSubagentDepth` | 1 | 顶层可以派子智能体；子智能体不能再派 |
| `maxSubagentsPerTurn` | 4 | 每个回合最多 4 次 `task` 调用；超出返回错误结果，父继续 |

这两个是一期常量，不做设置项。以后要放开，改常量即可；预算和事件链路已经按「可能多层」写好。

### 5. 预算

- 父子共用一本账（轮数、工具次数），一起扣。`MaxRounds` / `MaxToolCalls` 是**整个回合**的上限，不是每个循环各一份。
- 共享轮次计数还有一个副作用：网关不给 tool call id 时，内核按 `call_<轮次>_<序号>` 生成，共享计数天然避免父子 id 撞车。
- 子循环预算耗尽时**不做收尾轮**（那是父的活）：直接把已有内容作为报告交回，并注明「预算用完，报告可能不完整」。父拿到报告后自己决定怎么收尾。
- 子的每轮 token 用量由事件泵累加，结束时并入父的用量账；成功和失败都算。轮数和工具次数已经在共享账本里，报告时不要再加一遍。

### 6. 事件

子的事件转发到父的通道，打上 `ParentToolCallID = 父的 task 调用 id`。只打在没有父标记的事件上，为以后多层留余地。

| 事件 | 处理 |
|---|---|
| `text` / `reasoning` | 转发，带父标记 |
| `tool_start` / `tool_args` / `tool_end` | 转发，带父标记（`StreamEvent` 和 `ToolCall` 两处都要带） |
| `usage` | 不转发；累加到父的用量账 |
| `compacted` | 不转发。子的摘要是临时的，父不能拿它的边界 |
| `done` | 不转发。只取报告、停止原因、总量 |
| `error` | 不转发。转成 `task` 的错误结果，父继续 |

子循环结束时，事件泵补一个「思考收尾」事件（新增 `EventReasoningDone`），避免嵌套思考块永远转圈。父取消时 ctx 一起传下去，子自动停。

### 7. 结果

- 报告 = 子智能体**最后一次工具调用之后**的文本。之前的旁白不算报告；如果子没有工具调用，整段文本就是报告。
- 报告作为 `task` 的工具结果交给父模型。
- 报告为空时返回「子智能体没有给出报告」，不让父看到空结果。
- 报告过长时截断并注明（先定 32k 字符）。
- 界面：报告同时出现在展开区（流式）和抽屉（工具结果）。**接受这个重复**：主界面只有一份；存储翻倍可忽略；真正要防的是下一轮上下文重复，见下一节。

### 8. 历史重放（关键）

下一轮重建上下文时，必须把子智能体的内容过滤掉，否则隔离白做：

- **文本**：只取 `parent_tool_call_id` 为空的文本块。子的中间文本和报告不再以「助手说过的话」进上下文。
- **工具调用**：只重放顶层的工具调用。子的 `read` / `grep` 不重放。
- 报告只以 `task` 的工具结果出现一次。
- **不改表结构**：`chat_tool_calls` 没有父字段，重放时从消息内容块里收集「子工具 id」，把这些 id 排除即可。

现状是 `ExtractPlainText` 会把消息里所有 text 块拼起来（包括子的），`builtinToolCalls` 也不区分父子。这两处都要改。

### 9. 失败

| 情况 | 处理 |
|---|---|
| 子失败 / 超时 | 作为错误工具结果回父，父继续 |
| 父取消 | 子一起取消，父按取消结束 |
| 子报告为空 | 返回「子智能体没有给出报告」 |
| 子报告过长 | 截断并注明 |
| 子预算用完 | 有报告就返回，并注明「报告可能不完整」；没有报告返回错误结果 |

## 事件形状示例

父智能体接到「查一下仓库里所有处理支付的代码」：

```
父: tool_start(task, {description:"查找支付相关代码", prompt:"..."})
   子: reasoning "先搜 payment"              parent=call_task
   子: tool_start(grep)                      parent=call_task
   子: tool_end(grep)                        parent=call_task
   子: reasoning "再看这两个文件"             parent=call_task
   子: tool_start(read)                      parent=call_task
   子: tool_end(read)                        parent=call_task
   子: text "共 12 个文件：internal/pay/…"    parent=call_task
父: tool_end(task, output="共 12 个文件：…")
父: text "我查到 12 个文件，主要是……"
```

界面上：`task` 卡片展开后是子智能体的思考 / grep / read / 报告；卡片详情里是同一份报告。父的最终回答在卡片下面。

## 测试

- **内核**：深度到顶的子没有 `task` 工具；子权限不放大；共享预算到顶；父取消传到子；子失败回错误结果；报告为空；报告取最后一次工具调用之后的文本。
- **事件**：子事件带父 id；子的 `done` / `error` / `compacted` 不转发；嵌套思考块能收尾。
- **翻译**：`thinking_done` 带父 id；`tool_use` 的 `ParentToolCallID` 同时设置在 `StreamEvent` 和 `ToolCall` 上。
- **历史**：一条带嵌套块的消息，重放只含顶层文本和 `task` 调用/结果，不含子的 `read` / `grep`。
- **前端**：现有 `ContentBlocks` 的嵌套分组测试已覆盖；可补一个 `task` 卡片快照。

## 风险

1. **成本**：每次派生都是真实模型调用，token 会涨。共享预算 + 每回合 4 个上限兜底。
2. **延迟**：父同步等待，看起来像卡住；但展开卡片能看到子在跑（步数 + 转圈）。
3. **信任**：子读到的不可信内容会以「报告」形式回到父，父要自己判断。这和父自己读是同一类风险，不是新洞。
4. **调试**：子过程默认折叠，排查时要展开。
5. **后台任务也会具备**：会议纪要、Skill 提取等走 `RunSync` 的路径同样会拿到 `task` 工具。一期先观察；如果实测发现后台任务乱派子智能体，再加关闭开关。

## 分期

一期 = 本文范围：同步 `task`、一层递归、同权限、共享预算、事件嵌套、历史过滤。

二期候选：并行 / 异步、子智能体类型预设、子智能体专用模型、团队面板展示。
