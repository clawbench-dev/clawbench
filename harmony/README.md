# HarmonyOS 客户端（实验性）

基于 ArkTS / ArkUI Stage 和 ArkWeb，复用安卓本地登录页及服务端 Vue 工作台。当前开发版 `0.2.4 / 204`，客户端协议 `1`，沿用包名 `com.clawbench.harmony`，声明支持手机和平板。本轮包含凭据恢复、宿主桥契约、TLS 诊断与双语反馈修复，保留文件、分享、通知、媒体授权和原生 SSH / HTTP2 隧道。启动与已有功能不依赖 Push Kit；系统冻结或结束进程后的后台通知仍为已知限制。尚未达到 Android 全功能对等，暂不加入正式发布流水线。

## 开发与构建

本轮环境：DevEco Studio 26.0.0.851、SDK 26.0.0.105、Hvigor 6.26.8、ohpm 26.0.0.630。兼容 / 目标 API 23（HarmonyOS 6.1），编译 API 26；API 23 真机未验收。

将环境变量 `DEVECO_ROOT` 指向本机 DevEco Studio 安装目录，在仓库根目录构建：

```powershell
./scripts/build-harmonyos.ps1 -DevEcoRoot $env:DEVECO_ROOT
```

也可以用 DevEco Studio 打开 `harmony/`。原始产物在 `harmony/entry/build/default/outputs/default/`，构建脚本另导出根目录 `release/ClawBench-0.2.4-unsigned.hap`，默认未签名；实际构建结果和校验值见维护记录。签名配置应由开发者本地提供，不提交证书、私钥、密码、实际服务器地址或账户。

原生 CMake 构建包含 arm64-v8a / x86_64，首次构建需联网获取固定版本及 SHA-256 的 libssh2、mbedTLS、nghttp2 等公开依赖和 CA 数据。SSH 使用 libssh2 + mbedTLS，HTTP2 使用 nghttp2；TLS 校验主机名与受信 CA，SSH 首次连接或主机密钥变化需确认。不能通过跳过证书 / 主机身份检查解决连接失败。

Node.js 24 单元与登录页契约测试：

```sh
npm ci --prefix harmony
npm --prefix harmony test
```

鸿蒙测试独立于根目录 Vitest；jsdom、TypeScript 和夹具依赖只用于开发测试，不进入 HAP。契约测试执行实际打包的 bootstrap，用 TypeScript AST 检查 `web/src/utils/clawbenchNative.ts` 的每个必需成员，并覆盖真实 RPC 应答和失败传播。前端宿主回归仍使用根目录既有 Vitest、类型检查和构建流程。

`HarmonyOS` 工作流自动运行 Node 契约与 C++ 核心回归，接口声明变化也会触发检查。这些作业不能代替 ArkTS 编译。手动调度时可启用默认关闭的 `build_hap`，在带 `self-hosted`、`Windows`、`X64`、`harmonyos-sdk-26` 标签的预配 runner 上构建未签名 HAP；仓库变量 `DEVECO_ROOT` 必须指向配套 DevEco 安装。仅对已审阅提交使用该入口，runner 不存放签名密钥；PR 事件不会运行这个自托管作业，本轮尚未执行远端 HAP 作业。

## 当前能力

- 本地服务器列表、命名、增删改、协议健康检查与原生 `/login` 认证。
- Preferences 保存非敏感偏好，AssetStore 按归一化服务器地址保存密码。密码不回传给远程页面，本地登录页仅持有临时引用。
- 单个保存密码不可读时保留全部服务器条目，允许手动输入或在本次会话忽略已保存凭据；忽略模式不读写密码资产，仍要求服务端认证。重试和通知跳转保留明确的目标服务器。
- `setSSHPassword` 通过实际 RPC 及时更新当前隧道密码及日志脱敏，再按接收时的服务器地址串行保存安全凭据；已接收写入与后续保存、删除、登录共用队列，不因页面关闭而错误改写新服务器，保存失败对用户报告。
- 独立本地 / 远程 ArkWeb 控制器、可信顶层文档白名单、随机消息端口、取消和连接代次过滤。
- 全面屏动态避让状态栏、挖孔、导航指示器；系统栏跟随实际页面背景，键盘使用 RESIZE，登录页允许滚动。
- 返回事件、前后台恢复 hook、常亮释放、外链、文件 / 多选 / 拍摄选择器、剪贴板授权读写和选区菜单。
- 认证流式下载、进度 / 取消、系统保存选择器和 ShareKit 导出；外部分享文件经沙箱复制及服务器 / 项目确认后上传。
- 原生通知授权、前后台连续事件订阅、后台 15 秒单飞补拉、去重、已读撤销与点击导航；前台抑制系统通知，设置页独立显示授权和接收状态。
- 摄像头 / 麦克风权限和 ArkWeb 录屏授权入口；录屏尚未取得可用流，见下方验证边界。
- 异步 NAPI SSH / HTTP2 正反向映射、恢复、端口冲突处理、按服务器保存配置和传输选择。
- 终端音量键桥及默认关闭的限量脱敏日志；旧文档 / 连接的异步响应和错误不能覆盖新页面。
- 前端独立识别 HarmonyOS，不启用 Android WebView CSS 补偿或 APK 更新；跨应用悬浮状态和 Live View 因资格 / 签名权限受限保持 `false`。
- 连接、凭据、通知、文件和分享等失败提供中英文消息，文件反馈、通知标题和状态错误随语言设置即时刷新。TLS 证书、协商、CA 配置、DNS、超时和网络权限错误分别分类，不关闭证书或主机名校验。

当前没有应用内自签名证书信任例外或证书信任库，设置页只在宿主提供 `forgetTrustedCerts` 时显示证书管理。原生壳仍使用 `COLOR_MODE_DARK` 保持启动与加载外观；登录页、工作台网页主题和系统栏颜色独立同步，尚未完成原生控件随浅色网页主题切换。

## 验证与边界

0.1.3 阶段：25 项鸿蒙 Node 测试通过，未签名 HAP 构建成功；在 Pura 90 Pro / HarmonyOS 7 / API 26 / x86_64 模拟器验证安装、已保存凭据登录、服务器管理、竖屏安全区和聊天键盘布局。模拟器旋转检查时连接丢失，横屏设备验收待补。

0.2.0 阶段：双架构 NAPI 和未签名 HAP 已构建。模拟器已验证认证文件下载、35 B 原生保存及正确的进度 `done` 时机、35 B ShareKit 面板与取消、剪贴板授权读写、选区 Quote、后台发送通知和点击定位会话、摄像头 / 麦克风音视频轨道 live。面板打开不等于分享接收成功，媒体轨道 live 不等于完整会议通过。

SSH 与 HTTP2 的正向 / 反向分别各通过 6 轮模拟器数据测试，包含 2 MiB、慢读与并发，收发 SHA-256 一致。SSH 指纹 UI 与隔离测试服务公开密钥哈希核对后信任，实际传输为 SSH、连接成功，已有正反向映射自动恢复通过。hdc 测试转发层会提前关闭双向连接，半关闭因此无法验收，未计作通过。

上述 0.2.0 阶段的 Node、共享前端和传输选择器回归及类型检查曾通过；前端同时报告既有异步泄漏，不能把断言通过表述为全套运行零异常。0.2.3 增加接口成员、密码 RPC、凭据故障恢复、连接错误分类、通知漏收与设置能力分支回归，最终测试结果单独记录在维护记录中，不沿用历史计数。本次未完成设备安装与启动复验，历史模拟器结果不能作为本次后台消息真机问题已解决的证据。

生产 C++ 核心的流复位、背压清理、容量排队及 SSH EAGAIN 回归在 OHOS x86_64 模拟器通过。最终 HAP 的两种传输、正反向共四个方向各完成 40 次中断写后 55 次成功往返；实际回退端口可用，系统浏览器前台经原生隧道打开夹具页面通过。该次前后台切换不计作长时保活证明。可复用的原生夹具和压力脚本见 [Native Tunnel Regression](tests/native/README.md)。

录屏仅视频和请求音频两种场景均在授权后挂起，尚未取得可用流，仍需排查。通知和已有隧道仅在应用进程获准运行时工作，不保证系统挂起 / 结束后的即时送达或连接存活。Forge 事件当前没有服务端 pending 补拉契约，不承诺挂起后的补发。

0.2.3 先静默建立 HTTP 基线并持久记录空历史；HTTP 补拉游标仅由 pending 行推进，网页和实时事件只记录已见状态，同会话及有效 `message_id` 的完成回复跨两条路径去重。游标失效时保留旧游标之后的新行，避免新回复被当作整批历史静默丢弃。该修复未接入 PushKit、系统调度扩展或常驻后台任务，不能代替系统挂起或杀进程后的投递方案。

0.2.3 真机复测仍收不到后台通知：保留最近任务时进程和页面均为 `BACKGROUND`，两次进程 `cgroup` 包含 `freezer:/Frozen`；设备不允许读取 `freezer.state`，未宣称取得内核冻结状态值。原生 WebSocket 和定时补拉依赖进程执行，不能保证此场景送达。系统级推送还需云端及签名身份、token 生命周期、账号隔离、服务端发送授权、消息分类和跨通道去重等整条链路。维护者决定在 0.2.4 停止 Push Kit 接入，本 PR 不包含厂商云推送，也不把该后台问题标记为已修复。

0.2.4 的未签名 HAP 已完成 ArkTS 编译与双架构验包，270 项鸿蒙回归和共享前端类型检查通过。该结果证明已覆盖路径无需云推送配置，不代替新包设备安装、长时后台或完整业务验收。

端口与外链当前使用系统浏览器，具有独立 Cookie / 存储且不注入应用桥；不宣称与 Android 内嵌 sandbox 的会话保持等价。跨应用悬浮状态与 Live View 待平台资格，普通通知不算对应能力的替代验收。

尚未验收 ARM64 / API 23 真机、同版本 Android 逐像素对照、平板 / 分屏 / 大字体、全主题、长时后台，以及完整业务回归。实际分享接收方、外部分享导入、拍摄文件、文件传输异常组合、其他通知类型与冷启动、隧道网络切换及异常恢复仍需设备验收；自签名证书信任与自动更新也未完成。最终构建标识和测试数量见维护记录。
